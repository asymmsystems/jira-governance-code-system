# Partner kit: Jira Governance Suite for regulated migrations

Prepared 2026-11-08. For Atlassian Solution Partners who move regulated Jira customers from Data Center to cloud. Markdown now; each brief fits one page and can become a PDF later.

Nothing here has been sent. The owner decides on every contact (`docs/launch/regulated-enterprise-playbook.md`, section 7).

| File | What it is | For |
|---|---|---|
| `suite-overview.md` | The four apps on one page | Partner, customer |
| `ledgerseal-brief.md` | Approval seals and change control | Partner, QA or compliance lead |
| `definitionguard-brief.md` | Enforced Definition of Done | Partner, engineering or QA lead |
| `fourrealities-brief.md` | Delivery evidence per issue | Partner, audit preparation |
| `cascadeplan-brief.md` | Timeline, dependencies, baselines | Partner, planners |
| `governance-checklist.md` | Migrating regulated Jira to cloud: governance checklist | Partner, migration lead |
| `target-partners.md` | Target Solution Partners from Atlassian's public directory, with reasons | Owner only (internal) |
| `intro-note-DRAFT.md` | A draft intro note | Owner only. DRAFT, not sent |

Rules for every file:

- The wording follows the listing files in `docs/marketplace/`. If a listing changes, change the brief.
- Every brief has "What it does not do". Keep it.
- Before a brief goes to anyone, check: is the app listed? If not, say "pending Marketplace approval". Isolated Cloud and Government Cloud are "planned" until the listings exist.
- No Marketplace links until launch day (`docs/launch/launch-day-runbook.md`).
