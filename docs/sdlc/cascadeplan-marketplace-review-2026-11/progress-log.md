## 2026-11-06: pentest finding ASYMM-SEC-04 (CSV formula injection)

Branch `feature/cascadeplan-csv-injection`, from `master` at `a5e834a`. The finding is in `docs/security/pentest-report-2026-11-06.md` (branch `feature/pentest-2026-11-06`, commit `932b140`), section "Finding ASYMM-SEC-04".

### SEC-04. The baseline CSV export neutralises formula cells

- **Every CSV the app produces:** one. `baselineCsv` (`src/domain/baseline.ts`) builds it; the `exportBaseline` resolver (`src/server/baselines.ts`) returns it with one app-written comment line for left-out items; `src/frontend/baseline-panel.ts` downloads it ("Export CSV") or shows it in a read-only text box. A search of `src/` for `csv`, `download`, `Blob`, `createObjectURL`, `text/plain`, `clipboard`, `export` and `join(',')` found no other CSV, TSV or spreadsheet output (`legacy-planner.js` uses `text/plain` only for drag and drop).
- **What changed:** new `src/domain/csv.ts` with `csvCell` and `csvRow`, used for every cell of `baselineCsv`. Text that starts with `=`, `+`, `-`, `@`, a tab (0x09) or a carriage return (0x0D) gets a leading single quote (OWASP CSV Injection). Then RFC 4180 quoting: a cell with a comma, a quote, a line feed or a carriage return is wrapped in quotes, with each quote doubled (the carriage return is new; before, a bare CR was not quoted). The comment line is now three cells, `# <name>`, `frozen <time>` and `SHA-256 <digest>`, joined by `, ` as before. Before, the name was quoted after `# `, so a spreadsheet split a name with a comma or a line break and the next cell could start a formula. A plain name gives the same line as before; a name with a comma or a quote now gives `"# Q4, ""final""", frozen ...`.
- **Rule for numbers:** a value of type `number` is written by the app (the Jira estimate, `estimate_hours`), so it is written as is and stays numeric, negative values included (`-2` stays `-2`). Every other value is text and is neutralised, even when it looks like a number: issue ids and keys are strings, and a stored string such as `-2+3` in any column becomes `'-2+3`. Dates and `yes`/`no` are app-written text and never start with a trigger character.
- **Proof:** new `test/csv-injection.test.ts` (6 tests) with `=HYPERLINK(...)`, `+1+1`, `-2+3`, `@SUM(1+1)*cmd|' /C calc'!A0`, tab and CR prefixes, quotes and commas in issue keys, issue ids and baseline names, and a hostile issue summary in the live read of the end-to-end export (summaries are never written to the CSV, ADR-009). The tests parse the CSV the way a spreadsheet does and check that no cell starts a formula. With the old `baselineCsv` 5 of the 6 fail; the sixth (`csvCell` unit test) fails without `src/domain/csv.ts`. `test/baseline.test.ts` "CSV quotes text and carries the digest" now expects the new comment line.
