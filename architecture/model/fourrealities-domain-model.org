* 2. KVS mapping (Forge KVS: 240 KiB per value, 25 operations per transaction)

| Logical entity | KVS key | Value | Bound |
|----------------+---------+-------+-------|
| ISSUE_ROW (snapshot) | =fr:p:{project}:chunk:{i}= | ={snapshotId, rows[]}= | 100 rows, measured 63,099 B |
| Snapshot meta | =fr:p:{project}:meta= | =SnapshotMeta=, written last | under 1 KiB |
| Project summary | =fr:p:{project}:summary= | =ProjectSummary= | under 2 KiB |
| TREND_POINT | =fr:p:{project}:trend= | =TrendPoint[]= | 52 points |
| Catalog override (reserved) | =fr:p:{project}:catalog= | =EvidenceCatalog= | under 8 KiB |
| GATE_EXCEPTION_EVENT | =fr:ex:{issueId}:{gate}:{at}:{seq}= | one event | under 2 KiB each; never rewritten |
| REWORK_NOTE | =fr:note:{issueId}:{at}:{seq}= | one note | under 2 KiB each |
| Site configuration | =fr:cfg:site= | dev field id, site host | under 1 KiB |
| Project registry | =fr:projects= | project keys | 500 keys |

Issue property =fourrealities-exception= holds only the *current* exception status per gate,
for other tools and JQL. It is a projection of the events, not the record of truth.

* 4. Flows

** 4.1 Daily snapshot (scheduledTrigger, as the app)

#+begin_src text
SnapshotManager
  1. SiteConfigAccessor.get()                     dev field id, site host
  2. JiraIssueAccessor.searchProject()            paged, cap 2,000
  3. ExceptionEventAccessor.currentByIssue()      one paged prefix query
  4. JiraIssueAccessor.remoteLinks(started ids)   8 at a time, inside the budget
  5. GateEngine.evaluate(facts, catalog)          per issue
  6. SnapshotEngine.mergeUnread(previous, now)    keep previous Intent when links unread
  7. MetricsEngine.row(), summarize()             RAI, rates
  8. SnapshotEngine.trendPoint(summary, at)
  9. SnapshotAccessor.save(), recordTrend()       chunks, then summary, then meta
#+end_src

** 4.2 Page view (as the viewer)

#+begin_src text
DashboardManager
  1. SnapshotAccessor.load()                      meta + chunks (build once if absent)
  2. JiraIssueAccessor.visibleIds()               id-only search as the viewer
  3. filter rows, MetricsEngine.summarize(visible)
#+end_src

** 4.3 Code exception approved by a project administrator (ADR-001, Option C)

#+begin_src text
 Requester (acc-1)                  FourRealities                         Approver (acc-2)
 ────────────────                   ─────────────                         ────────────────
 "Request exception" ─────────────► ExceptionPolicyEngine.canRequest()
   reason (15-500 chars)             (no PR, gate MISSING)
                                    ExceptionEventAccessor.append(REQUESTED, acc-1 as REQUESTER)
                                    property fourrealities-exception := {code: REQUESTED}
                                    Gate stays "Evidence missing";
                                    panel: "Exception requested by acc-1, awaiting approval"
                                                                       ◄─── opens the issue panel
                                    JiraPermissionAccessor.isProjectAdmin()  (as acc-2:
                                      mypermissions ADMINISTER_PROJECTS)
                                    ExceptionPolicyEngine.canTransition(
                                      REQUESTED → APPROVED, by acc-2)  ◄─── "Approve" / "Reject"
                                      rule: acc-2 is project admin,
                                            acc-2 ≠ requester, acc-2 ≠ assignee
                                    ExceptionEventAccessor.append(APPROVED, acc-2 as APPROVER)
                                    property := {code: APPROVED}
                                    Gate shows "Excepted: requested by acc-1,
                                    approved by acc-2 on <date>: <reason>"
#+end_src

All writes run as the user. A 403 from Jira returns to the user; there is no retry as the app.

* 5. Migration from specification v2

| v2 data | v3 form | Rule |
|---------+---------+------|
| =fr:issue:{id}:exception= with =code= | two events: REQUESTED and APPROVED by =code.recordedBy=, =migrated: true= | Panel labels it "approved before two-person approval was required". Old key kept until the next daily run confirms the events, then deleted. |
| =fr:issue:{id}:exception= with =rework= | one REWORK_NOTE | Same deletion rule. |
| v1 =fr:issue:{id}:exception= (type, reason) | read as v2 first (existing =normalizeException=), then as above | |
